# Spike S5 — Tooling skeleton

- Status: Done
- Roadmap: Phase 0, S5
- Settles: RFC 0002 "Cloudflare Vite plugin under Vite+ needs validation"; RFC 0008 "the Vite plugin under Vite+"

## Question

Can one toolchain, Vite+ (`vp`) with Bun, run the whole stack? That stack is a Worker with a SQLite-backed
Durable Object, the React dashboard, the design tokens and the i18n catalog. `vp dev` should run the SPA and the
Worker locally, and `vp check`, `vp run -r test` and `vp run -r build` should pass in CI from a clean checkout.

## What was built

| Piece | Where | PR |
| --- | --- | --- |
| Worker + `WorkspaceDO` (SQLite), `wrangler.jsonc` with `dev`/`staging` | `apps/api` | #3 |
| Design tokens (TS source, generated CSS for Tailwind v4 and shadcn/ui) | `packages/ui` | #5 |
| Paraglide catalog in `en` and `pt-BR`, `Intl` helpers | `packages/i18n` | #6 |
| Workspace packages resolved from source in check, tests and dev | root, `packages/*` | #7 |
| Dashboard SPA on a Worker, forwarding `/api/*` to the api Worker | `apps/web` | this PR |

Versions: vite-plus 1.4.0 (Vite 8, Rolldown, Vitest 5.0.5, tsgo 7), `@cloudflare/vite-plugin` 1.65.0,
`@cloudflare/vitest-plugin` 1.4.7, wrangler 4.152.0 / workerd 1.20261019.1, React 19.3, TanStack Router 1.170,
Tailwind 4.3, shadcn CLI 4.22 on Base UI, Paraglide JS 2.29.

## Result

It works. `vp run dev` from the root serves the dashboard and runs the web Worker, the api Worker (as an
auxiliary worker) and `WorkspaceDO` together. `/api/*` goes through the web Worker and a service binding to the
api Worker, then to the Durable Object's SQLite. CI passes from a clean checkout and now also fails if a build
changes a committed file.

What needed a decision or a workaround:

- **Worker tests.** `@cloudflare/vitest-pool-workers` requires Vitest 4 and does not run on Vite+'s Vitest 5.
  Its successor `@cloudflare/vitest-plugin` does, with tests inside workerd. It ignores `run_worker_first` under
  `SELF`, so the web Worker's routing is tested against its real config with wrangler's test harness instead.
- **Environments are chosen at build time.** With the Vite plugin, `CLOUDFLARE_ENV` picks `dev` or `staging` when
  building; `wrangler deploy` does not take `--env`. RFC 0002's Environments section says so.
- **Generated files are committed** (`worker-configuration.d.ts`, the Paraglide output, the token CSS, the route
  tree): CI runs `vp check` before any build. Each has a staleness check, and the final CI step catches the rest.
- **Workspace packages resolve from source** under the scoped `@freecorps/source` export condition, generated by
  `vp pack` and enabled by `customConditions` and the `workspaceSource()` plugin (RFC 0002).
- **Paraglide without its Vite plugin.** `packages/i18n` compiles itself with the compiler API and ships the output.
  Consumers just import ESM. Under esbuild (Wrangler) `m.x` does not tree-shake, so Workers import messages by name
  (RFC 0008).
- **Durable Object SQLite** refuses `sqlite_version()` and similar functions ("not authorized").
- **shadcn/ui** initialises non-interactively only with a preset (`-p`). Its theme block, Geist font and neutral
  palette were replaced by `packages/ui` tokens, and components restyled to Brigade's focus, destructive and
  touch-target rules.
- **Bun on this machine is 1.3.14** while `devEngines` pins 1.4.4; `vp add --filter` needs 1.4. CI downloads the
  pinned version.
- **`vp check` reads only the root** `fmt`/`lint` blocks, so ignore patterns for generated files live in the root
  `vite.config.ts`.

## Decision

Keep Vite+ as the single toolchain (RFC 0002 unchanged in substance). Use the Cloudflare Vite plugin for every
Worker; use `@cloudflare/vitest-plugin` for tests that need workerd, and wrangler's test harness where the asset
routing itself is under test. Ship the dashboard as a SPA on Workers static
assets behind a small Worker that forwards `/api/*` through a service binding.

Open for later spikes: Hermes `Intl` support and Metro resolution of `@freecorps/source` (S4); bundle size of the
dashboard (159 kB gzip, mostly React and TanStack Router) once real screens exist.
