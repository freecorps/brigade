# RFC 0008 — Internationalization

- Status: Draft

## Scope

Every user-facing surface is localized: web dashboard, mobile app, public site/docs, Slack messages, push
notifications, emails, status pages. Launch locales: `en` (source) and `pt-BR`.

## Decisions

- **One catalog package** (`packages/i18n`) with ICU MessageFormat messages, consumed by web, mobile and server.
- **Source language is English**; keys are semantic (`incident.status.investigating`), not English sentences.
- **Server-rendered messages are localized per recipient**, not per workspace: Slack DMs, emails and push use the
  recipient's locale stored on their user/device profile. Shared Slack channels use the workspace default locale.
- **Push and encryption:** the instance renders the notification text in the device's locale before encrypting
  (RFC 0006), so the NSE only decrypts and displays.
- **Dates, durations and numbers** via `Intl` (available in Workers, browsers and Hermes).
- **Domain values stay canonical** in data and API (`sev1`, `investigating`); only the UI translates them.
- **User content is not translated** (incident titles, updates). Optional AI translation is a later feature.

## Library: Paraglide JS

Chosen over i18next and Lingui because:

- **Compiles messages to plain typed functions** (`m.incident_declared({ number })`) — no runtime catalog loader,
  tree-shakes per bundle (matters for Workers size limits and mobile startup).
- **Explicit locale per call** (`m.incident_declared(params, { locale: "pt-BR" })`). The server renders Slack DMs,
  emails and push text for each recipient's locale without request-global state.
- **Framework-agnostic output**: the same compiled package works in Workers, the React dashboard, TanStack Start
  (site/docs, which has an official Paraglide example) and React Native.
- Type errors when a key or parameter is missing.

`packages/i18n` holds the message sources (one JSON file per locale) and exports the compiled functions plus
`Intl` helpers. To validate in spikes S4/S5: plural rules on Hermes (`Intl.PluralRules`) and the Vite plugin under Vite+.

## Site and docs

Public site and docs in `apps/site`, built with Fumadocs on TanStack Start, with per-locale routes
(`/en/...`, `/pt-br/...`) using Fumadocs' i18n support. Prerendered pages must be listed per locale.
Translation workflow: PRs to catalogs; consider Weblate/Crowdin (free tiers for open source) once the community grows.
