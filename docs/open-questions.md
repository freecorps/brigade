# Open questions

Decisions we still need to make. Each one links to the RFC it affects. Once decided, the answer moves to the
"Decided" section below and into the RFC.

## Q8 — Critical Alerts entitlement (RFC 0006)

Owner: Freecorps Apple developer account holder. The bundle ID `app.freecorps.brigade` exists, so apply now;
mention on-call paging (PagerDuty/Opsgenie precedent). Everything that does not need the grant is built and off
behind `BRIGADE_CRITICAL_ALERTS=1`; RFC 0006 "Critical Alerts" lists the steps once Apple grants it.

## Q13 — PSTN provider choice (RFC 0010)

Deferred: in-app VoIP calls (RFC 0010) cover calling for now. The `VoiceProvider` contract is defined; pick the first
implementation by price for Brazilian numbers (Twilio vs local providers) when a PSTN step is taken up.

## Q18 — What is left of who is paged (RFC 0005, RFC 0006)

Decided (see the table below): a severity threshold per policy, a policy picked when declaring by hand, the "a page
reached nobody" email to owners and admins, no early escalation on missing receipts, one summary line for many members
without a device, and the activity-driven member reconcile. Still open:

- An exhausted run falls back to everyone who can respond once; should a workspace be able to turn that off, or point
  it at a smaller group?
- Should the external dead-man switch hear of a page that reached nobody too?
- Should the app treat `403 not_a_member` on a kept sign-out as finished, since the removal already freed the phone
  (RFC 0006 "A handed-over phone")?

## Q19 — What else the dead-man switch should prove (RFC 0007)

Decided (see the table below): a deep relay health check, one D1 read per beat, and an email to `OPERATOR_EMAILS` on
`brigade.status_changed`. Still open:

- Each workspace shard's own alarm and drain: have the watchdog read a cheap liveness summary from shards with a
  backlog (the drain's `failures` and backlog size) and turn `degraded` past a threshold. Needs a registry of shards,
  which does not exist yet.
- Whether paging Brigade's operators on a monitor stuck at `unknown` should ride on this switch (it carries no
  workspace data today).
- `GET /health/paging` says only `{ status }` without a session or to a user in no workspace, the reasons and times to
  any member, and `external` to nobody (operators read it in the logs). Should `OPERATOR_EMAILS` also stand in for an
  instance-operator role, so the dashboard shows `external` to them?

## Q21 — What is left of the caps on email to people (RFC 0005 "Abuse", RFC 0002 "Auth")

Decided (see the table below): every cap stays except invitations per address, verification before sign-in is an
instance setting, an instance without email has closed sign-up, and sign-up is closed by default. Still open:

- Should an address be able to opt out of invitations altogether?
- Password reset: should a request get through anyway when the address's last link has expired, rather than wait out
  the 10 a day?
- Sign-up timing: the noise between a taken and a free address's D1 writes is bounded by the sign-up rate limit (3
  per IP in 10 s). Is that enough, or should sign-up answer after a fixed delay?

## Q23 — What is left of the status page (RFC 0012)

Decided (see the table below). Still open:

- Uptime counts an alert firing as downtime and anything else as up, including a degraded component the team set by
  hand. Earlier pauses are not kept, so they count as up. Should pauses be kept so they always show as no data, and
  should hand-set or incident impact count as degraded? An hour of downtime makes a day `down`; is that the right
  line?
- The large-provider list for subscriber confirmations is short and fixed in code (`src/status-subscribers.ts`):
  should an instance be able to extend it?

## Q24 — What is left of follow-ups and postmortems (RFC 0013)

Decided (see the table below). Still open:

- Should the hour of follow-up reminders be a member's choice, and should reminders also go a day before the due
  date?
- Should an instance operator be able to pick another Workers AI model for drafts without a deploy?
